# 자동화 스케줄

스탬프 이벤트는 사람 손을 타지 않고 매일 여섯 단계로 돕니다. 모두 **한국시간** 기준입니다.

## 하루의 흐름

| 시각 | 작업 | 하는 일 |
|---|---|---|
| **00:05** | 이용권 만료 처리 | 전날 23:59:59 로 기간이 끝난 미사용 이용권을 만료로 전환 |
| **10:00** | 미사용 안내 | 만료 30일 이하 이용권 보유자에게 알림톡 |
| **15:10** | 예약 수집 | 전일자 예약을 외부 수집 서버에서 가져옴 (쿠폰 사용 내역 포함) |
| **15:20** | 이용권 지급 | 수집된 예약으로 스탬프 계산 → 조건 충족 시 발급 |
| **15:30** | 최초 적립 알림톡 | 처음 스탬프가 생긴 고객에게 |
| **15:40** | 이용권 지급 알림톡 | 그날 발급된 이용권 안내 (최근 7일 실패분 재시도 포함) |

::: tip 왜 이 순서인가
**수집 → 계산 → 안내** 순서가 어긋나면 그날 데이터가 통째로 밀립니다.
15:10 수집이 실패하면 15:20 계산이 전날 데이터로 돌고, 그 결과로 알림톡이 나갑니다.
그래서 앞 단계가 뒷 단계보다 항상 먼저입니다.
:::

## 수집이 실패하면

**담당자 휴대폰으로 문자가 갑니다.** 로그만 남기고 넘어가지 않습니다.

```
[우리끼리] 스탬프 예약수집 실패

09/03 15:10 예약 수집에 실패했습니다.

2026-09-02 — HTTP 404 · 데이터 없음

이대로 두면 오늘 15:20 스탬프 집계·이용권 지급이
이 날짜를 빼고 돌아갑니다.
원인 해결 후 관리자 화면 > 스탬프 > 수집 예약에서 재수집하세요.
```

| 문자에 찍히는 사유 | 원인 | 대응 |
|---|---|---|
| `HTTP 404 · 데이터 없음` | 수집 서버가 그날 파일을 아직 안 만듦 | 잠시 뒤 재수집 |
| `수집 서버 연결 실패 (터널 확인 필요)` | 사내 수집 PC 또는 터널이 꺼짐 | PC·터널 상태 확인 |

### 다시 수집하는 법

관리자 화면 → 스탬프 이벤트 → **수집 예약** 탭에서 빠진 날짜를 확인하고 다시 수집합니다.
**같은 날짜를 여러 번 수집해도 안전합니다** — 이미 있는 예약은 바뀐 값만 갱신됩니다.

수집을 다시 하면 그 뒤 계산은 다음 날 15:20에 저절로 따라잡습니다.
스탬프를 저장하지 않고 매번 다시 계산하기 때문입니다.

## 알림톡이 안 나갔을 때

먼저 **발송로그** 탭에서 실패로 남았는지 확인합니다.

- **실패로 남아 있다** → 사유를 보고 원인을 없앱니다. 재시도는 자동입니다
- **아예 기록이 없다** → 대상이 없었거나 작업 자체가 돌지 않은 것입니다

## 이용권 만료는 크론을 기다리지 않는다

만료 크론은 **상태 표시를 맞추는 일**만 합니다. 실제로 쓸 수 있는지는
**사용하려는 순간 유효기간을 직접 확인**해서 막습니다.

크론이 며칠 걸러져도 기간이 지난 이용권은 사용되지 않습니다.
반대로 크론만 믿고 상태 컬럼으로 판정하면, 기간이 끝난 이용권이
「사용 가능」인 채로 남아 그대로 처리됩니다.

## 로그

작업별로 서버에 로그 파일이 쌓이고, 매일 회전하며 14일치를 보관합니다.
사람이 확인해야 하는 내용은 모두 화면(발송로그 · 수집 예약 탭)에서 볼 수 있게 해 두었습니다.
