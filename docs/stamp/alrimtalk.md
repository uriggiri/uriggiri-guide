# 알림톡

자동으로 나가는 것이 세 가지, 손으로 보내는 것이 하나 있습니다.
발송 결과는 성공·실패 모두 **건별로 남고**, 관리자 화면 [발송로그](/stamp/admin#발송로그) 탭에서 봅니다.

## 자동 발송 세 가지

| | 언제 | 누구에게 | 몇 번 |
|---|---|---|---|
| **최초 적립** | 매일 15:30 | 이벤트 기간 중 처음으로 스탬프가 생긴 고객 | 사람당 1회 |
| **이용권 지급** | 매일 15:40 | 스탬프 10개를 채워 이용권을 받은 고객 | 이용권마다 1회 |
| **미사용 안내** | 매일 10:00 | 만료가 30일 이하로 남은 미사용 이용권 보유자 | 이용권마다 1회 |

**순서가 중요합니다.** 처음 이용한 고객이 그날 바로 10개를 채우는 일은 없지만,
안내의 흐름상 「적립 시작」이 「지급 완료」보다 먼저 나가야 하므로 15:30 → 15:40 순으로 둡니다.

### 적용 시점

최초 적립은 **이벤트 시작일 오전 9시 이후 이용 완료된 예약**부터 셉니다.
이벤트를 열기 전에 쌓인 예약으로 알림톡이 나가지 않게 하는 장치입니다.

## 중복과 재시도

**같은 사람·같은 이용권에 두 번 나가지 않습니다.** 성공 이력이 있으면 다음 실행에서 제외합니다.

**실패는 자동으로 다시 시도합니다.**

| | 재시도 범위 |
|---|---|
| 최초 적립 | 성공할 때까지 매일 |
| 미사용 안내 | 만료 30일 이하로 남아 있는 동안 매일 |
| 이용권 지급 | 발급 후 **7일 이내** 건까지 매일 |

일시적인 발송 실패나 템플릿 승인 지연은 이 재시도로 스스로 복구됩니다.

## 손으로 보내는 것

**미달성 독려 알림톡** — 스탬프를 모으는 중인 고객에게 남은 개수를 알립니다.
자동으로 나가지 않고, 관리자가 대상을 확인한 뒤 보냅니다.

## 템플릿 관리

이벤트마다 세 종류의 템플릿을 따로 지정합니다 (이벤트 관리 화면).
템플릿 본문에는 스탬프 개수·금액이 **고정 문구로** 들어가므로,
이벤트가 바뀌면 템플릿도 함께 바꿔야 합니다.

::: warning 카카오 검수를 통과해야 나갑니다
승인되지 않은 템플릿으로 보내면 **전건 실패**합니다 (`유효한 템플릿 아이디가 아닙니다`).
실패는 이력에 남고 다음 실행에서 자동 재시도되므로, 승인만 되면 별도 조치 없이 발송됩니다.

혜택 지급·이벤트 안내는 광고성으로 분류되기 쉬워 반려가 잦습니다.
반려 사유에서 요구하는 **발송근거 문구**를 본문 하단에 고정으로 넣어야 통과합니다.
:::

## 실패했을 때 보는 곳

관리자 화면 → 스탬프 이벤트 → **발송로그** 탭.
실패만 걸러 보면 사유가 함께 나옵니다.

| 자주 나오는 사유 | 뜻 |
|---|---|
| 유효한 템플릿 아이디가 아닙니다 | 템플릿이 아직 승인되지 않았거나 반려됨 |
| 수신거부된 번호입니다 | 고객이 채널 수신을 거부함 |
| 이벤트 지급 템플릿 미설정 | 이벤트 관리에서 템플릿 지정이 비어 있음 |
