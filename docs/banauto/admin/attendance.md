# 출퇴근 관리

`통합관리 → 출퇴근 관리`

날짜를 하나 고르고, 그날 전 지점의 출퇴근을 봅니다.

## 날짜 이동

`◀ 날짜 ▶` 와 「오늘」 버튼이 붙어 있습니다. 다른 화면의 날짜 이동과 같은 모양입니다.

## 기록 이상 표시

숫자가 이상할 때 값을 조용히 맞추지 않습니다. 타일 오른쪽 위에 표시를 얹고,
**이유를 툴팁으로** 보여줍니다.

| 표시되는 경우 | 뜻 |
|---|---|
| 중복 출퇴근 | 같은 사람이 하루에 두 번 이상 |
| 근무 0분 | 출근과 퇴근 시각이 같음 |
| 퇴근 누락 | 지난 날짜인데 퇴근 기록이 없음 (오늘은 근무 중일 수 있어 제외) |
| 시간 겹침 | 앞 기록이 끝나기 전에 다음 출근 |

색은 주황입니다. 빨강은 「틀렸다」라서 너무 셉니다 — 여기서 필요한 뜻은
**「사람이 확인해야 한다」** 입니다.

## 영업일이라는 단위

출퇴근은 **달력의 하루가 아니라 매장의 영업일**로 묶입니다.
[환경설정](/banauto/admin/settings#출퇴근-설정)의 인정 시간이 그 경계입니다.

::: warning 자정을 넘는 매장
인정 시간이 `18:00 ~ 10:00` 이면 영업일 경계는 **오전 10시**입니다.
- 8/30 21:00 출근 기록의 영업일 = `8/30 10:00 ~ 8/31 10:00`
- 그래서 **8/31 오전 10시 이전**에 다시 출근을 누르면 같은 영업일로 묶여
  「이미 출근 처리되었습니다」로 막힙니다
:::

## 기록이 없을 때 확인하는 순서

「분명히 출근했는데 기록이 없다」는 문의가 옵니다. 순서대로 봅니다.

1. **지점 상세 → 「실패한 출퇴근 시도」**를 엽니다
   - 「이미 출근 처리됨」이 있다 → 위의 영업일 경계에 걸린 것입니다.
     같이 표시되는 **「인정 시각」**을 보세요. 사진에서 읽은 시각이 하루 어긋나면 여기서 막힙니다
   - 「반경 밖」·「WiFi 불일치」 → 현장 조건 문제입니다
   - **아무것도 없다** → 요청이 서버에 도달한 적이 없습니다. 앱·네트워크 문제이거나 누르지 않은 것입니다
2. GPS 방식 매장이면 **「GPS 위치 측정 기록」**도 함께 봅니다 (누른 위치·정확도·매장 기준 좌표)
3. 실제로 근무한 것이 확인되면 **「직원 출근 대신 등록」**으로 채웁니다

::: tip 2026-09-02 이전 기록은 소급 확인이 안 됩니다
「실패한 출퇴근 시도」는 그날부터 쌓입니다. 그 전에는 사진 방식 매장의 실패가
아무 흔적도 남기지 않았습니다.
:::

## 출퇴근 방식 세 가지

| 방식 | 확인 수단 | 실패하는 자리 |
|---|---|---|
| 사진(OCR) | 촬영 사진의 시각 | 사진 없음 · 시각이 어긋남 |
| GPS | 매장 반경 안인지 | 좌표 미설정 · 위치 실패 · 반경 밖 |
| WiFi | 매장 WiFi 이름·라우터 | 미등록 · 다른 와이파이 |

관리자는 세 방식이 모두 안 되는 상황에서 **대신 등록**할 수 있습니다.
